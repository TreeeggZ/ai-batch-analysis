# 实现说明

## 从个人程序到Web工具

项目起初在个人电脑上运行。为方便他人使用，后续将分析程序接入Flask与HTML/JavaScript页面，并部署到平台环境。使用者通过浏览器上传文件、配置任务和下载结果，无需在各自电脑上配置分析环境。

## 把需求转换成配置

当时直接使用模型对话窗口打标，受上下文与单次处理量限制，难以一次完成大批量任务。工具将大任务拆成批次，按任务描述、字段和分类选项组织提示词，再统一整理输出。分批处理并不扩大模型自身的上下文窗口。

不同任务需要不同输出字段。例如，评论分析可以关注情感、问题类别和依据。配置化可以减少针对每次分析重写处理流程的需要。

## 流式接收与结构化结果

Python端接收SSE事件，聚合响应后解析JSON，再将结果写回表格。针对格式异常与超时设置有限重试、错误标记及结果备份，方便排查和复核。

结构化输出仍需检查内容是否符合任务要求，解析成功的结果也保留人工复核环节。

## 两类分析路径

| 路径 | 方法 | 用途 |
| --- | --- | --- |
| 配置化AI批处理 | AI应用平台API、动态提示词、SSE聚合、JSON解析 | 按任务处理用户反馈并输出指定字段 |
| Python NLP | jieba / TF-IDF | 提取关键词 |
| Python NLP | 预训练DistilBERT模型 | 情感分类 |
| Python NLP | BERTopic及文本嵌入、降维与聚类组件 | 提取讨论主题 |

情感分类使用从Hugging Face下载的预训练模型，主题分析使用BERTopic。参考文档按任务调整参数，并记录可复用配置。

## 模型API接入

通过类似Dify的AI应用平台创建模型调用接口。平台侧负责模型调用，Python侧负责分批请求、流式响应聚合、解析与文件输出。

README中的任务周期与累计数量为实际工作量估算；分析结论的准确性仍通过抽样复核判断。

## 两条路径的关系

Python NLP与AI批量标注目前分别使用：前者提供关键词、情感及主题分析，后者按自定义任务输出字段。曾考虑先做主题聚类，再交由LLM整理与分析各主题，但尚未尝试整合，不将其列为已实现流程或降本成果。

## 使用方式的变化

近期实际任务更多通过Agent配合Prompt完成分批标注，已不再主要使用这个Web工具。本项目展示的是此前完成的配置化批处理、响应解析、表格回填与Web交付实践；后续使用Agent不代表原工具已升级为Agent架构。
